Netlify Agent Runners GitHub Action

Mention @netlify with a request in any issue or pull request. A Netlify Agent Runner (Claude, Codex, Gemini or OpenCode) makes the change on Netlify and opens a pull request with a deploy preview. You review it and merge it; the action never merges anything itself.

Set it up in 4 steps View on GitHub

How it works

From a mention to a pull request

The action watches issues, pull requests and comments for @netlify. When it finds one, it starts an agent run on Netlify through the published nax-agent-runner-sdk, waits for that exact run, and lands the changes as an open pull request.

What it posts

Status comment

One comment that changes as the run goes: a short summary, deploy, agent and log links, and hidden state markers that let follow-up runs carry on.

Result comments

One comment per run that never changes afterwards: the prompt, what the agent did, a screenshot and links.

History

On a pull request, a compact table of contents of every result comment, newest first.

Issue redirect

Once a PR exists for an issue, a note on the issue sends people to the PR, where follow-ups go.

Setup

Four steps, one workflow file

You need a Netlify site linked to the repository, two secrets, and the workflow below.

  1. Install the GitHub App

    Install netlify-coding on your repository. It's what creates the commits and pull requests.

  2. Link a Netlify site

    Link the repo to a Netlify site, and note its Site ID from Site configuration > General.

    netlify init

  3. Add two repository secrets

    In Settings > Secrets and variables > Actions:

    SecretWhat it is
    NETLIFY_AUTH_TOKENA Netlify personal access token
    NETLIFY_SITE_IDThe site ID from step 2

  4. Add the workflow

    Save this as .github/workflows/netlify-agents.yml. It's the same as the repo's workflow template.

    name: Netlify Agent Runners

on:
  workflow_dispatch:
    inputs:
      trigger_text:
        description: 'What should the agent build or change? (e.g. "Add a dark mode toggle")'
        required: true
        type: string
        default: '@netlify'
      actor:
        description: 'GitHub username to attribute this run to'
        required: true
        type: string
      agent:
        description: 'Agent to use'
        required: false
        type: choice
        options:
          - codex
          - claude
          - gemini
          - opencode
        default: 'codex'
      model_id:
        description: 'Model (auto lets the backend choose; a model picks its own agent)'
        required: false
        type: choice
        options:
          - auto
          - claude-fable-5
          - claude-opus-5
          - claude-opus-4-8
          - claude-sonnet-5
          - claude-haiku-4-5
          - gpt-5.6-sol
          - gpt-5.6-terra
          - gpt-5.6-luna
          - gpt-5.4-mini
          - gemini-3.1-pro-preview
          - gemini-3.6-flash
          - gemini-3.5-flash-lite
          - moonshotai/kimi-k3
          - moonshotai/kimi-k2.7-code
          - z-ai/glm-5.2
          - deepseek/deepseek-v4-pro
          - ~deepseek/deepseek-v4-flash-latest
          - x-ai/grok-4.5
          - minimax/minimax-m3
        default: 'auto'
      effort:
        description: 'Effort level (auto lets the backend choose)'
        required: false
        type: choice
        options:
          - auto
          - low
          - medium
          - high
          - max
        default: 'auto'
      runner_mode:
        description: 'normal makes changes and opens a PR; ask answers a question in a comment without changing anything'
        required: false
        type: choice
        options:
          - normal
          - ask
        default: 'normal'
      recover_thread:
        description: 'Internal: issue or PR number whose unfinished agent run should be finished (used by the recovery workflow)'
        required: false
        type: string
        default: ''
  pull_request_target:
    types: [opened, reopened]
  pull_request_review_comment:
    types: [created]
  pull_request_review:
    types: [submitted, edited]
  issues:
    types: [opened, assigned, edited]
  issue_comment:
    types: [created, edited]

concurrency:
  # One agent job per issue or PR at a time; recover_thread dispatches share
  # the thread's group. A comment that is exactly "@netlify stop" gets its own
  # group so it runs right away instead of queueing behind the run it stops.
  group: ${{ (github.event_name == 'issue_comment' || github.event_name == 'pull_request_review_comment') && github.event.comment.body == '@netlify stop' && format('netlify-stop-{0}', github.run_id) || format('netlify-{0}-{1}', github.repository, github.event.pull_request.number || github.event.issue.number || inputs.recover_thread || github.run_id) }}
  cancel-in-progress: false

jobs:
  netlify-agent:
    if: >-
      github.event_name == 'workflow_dispatch' ||
      (
        github.event.sender.login != 'github-actions[bot]' &&
        github.event.sender.login != 'netlify-coding[bot]' &&
        github.event.sender.login != 'netlify[bot]'
      )
    runs-on: ubuntu-latest
    timeout-minutes: 25
    permissions:
      contents: write
      pull-requests: write
      issues: write
      actions: read   # recovery checks whether an earlier run's job is still alive
    steps:
      - uses: netlify-labs/agent-runner-action@v1
        with:
          netlify-auth-token: ${{ secrets.NETLIFY_AUTH_TOKEN }}
          netlify-site-id: ${{ secrets.NETLIFY_SITE_ID }}
          job-timeout-minutes: '25'       # Keep equal to this job's timeout-minutes above
          # Optional settings:
          # default-agent: 'codex'        # Default agent (claude, codex, gemini, opencode)
          # default-model-id: ''          # Default model (e.g. claude-fable-5 or fable); empty = Auto
          # default-effort: ''            # Default effort (low, medium, high, max*); empty = Auto
          # protected-paths: default      # Flag risky file changes; e.g. "default, infra/**" or "none"
          # protected-paths-action: comment # Add ",label" and/or ",draft" to escalate
          # scope-instructions: default   # Prompt guidance; "none" turns it off
          # manage-labels: 'false'        # Auto-create and apply labels
          # dry-run: 'false'              # Still starts an agent run; skips commit/PR creation
          # preflight-only: 'false'       # Validate setup only; starts no agent run
          # timeout-minutes: '10'         # Max wait for agent completion
          # netlify-cli-version: '24.8.1' # Netlify CLI version
          # timezone: 'America/Los_Angeles' # Timezone for rendered timestamps
          # debug: 'false'                # Enable debug logging

    Then open an issue that starts with @netlify to try it.

Talking to it

Say what you want after @netlify

Everything after the mention is the request. Before it, you can name an agent, a model and an effort level, in that order. Each one is optional.

@netlify Build a landing page for a coffee shop with a menu and contact form
@netlify claude Add a dark mode toggle
@netlify fable high Refactor the checkout flow          # claude + Fable 5, high effort
@netlify-fable high Refactor the checkout flow          # same thing
@netlify codex sol medium Add retry logic               # codex + GPT 5.6 Sol
@netlify gemini flash Summarize the changelog           # gemini + Gemini 3.6 Flash

The default agent is codex; change it with the default-agent input. A model picks its own agent, so fable means Claude, and if you name a model from a different agent the model wins and the status comment says so. Anything you leave out is chosen by the backend (Auto) unless you set default-model-id or default-effort.

The shorter Codex and Gemini names need the agent in front, so a prompt starting with "pro tip" isn't read as a model. Exact model IDs always work, and model:<id> anywhere on the @netlify line requests any model, including ones missing from this list.

Effort

Effort goes after the agent or model: low, medium or high (some OpenCode models also take max; Kimi K2.7 Code and MiniMax M3 take none). It only counts when a space, :, , or the end of the line follows it, so @netlify codex low-hanging fixes leaves effort on Auto. effort:<level> anywhere on the line wins over the positional word, and effort:auto forces Auto. If a model doesn't support the level, the action uses Auto and says so.

Typos and aliases

Common typos work: @nelify, @netlfy, @netify, @netlif, @netfly. So do @netlify-agent and @netlify-ai. Mentions inside code blocks or inline code are ignored, so you can quote @netlify without starting a run.

Asking questions

Ask about the code without changing it

Ask mode answers in a comment. It never changes files or opens a PR.

@netlify-ask How are webhooks retried?
@netlify ask: why does the ingest job retry twice?
@netlify claude sonnet mode:ask where is rate limiting configured?

A plain "ask" isn't enough, because @netlify ask the user to confirm… is a request to build something. Use the -ask suffix, ask: with its colon, or mode:ask right after the mention. Agent, model and effort words work the same as for normal runs.

The answer appears as a result comment marked 💬 Answered. On a PR, the agent reads the PR branch. On an issue, a later @netlify request continues from the same context, so "now build it" works. From the workflow's Run workflow form, choose runner_mode: ask.

Follow-ups and stopping

Keep iterating on the same PR

After the first run opens a PR, comment @netlify on the PR to ask for more. The agent carries on from where it left off. A follow-up only changes the model or effort when it names one.

Stop a run

Comment exactly @netlify stop. The agent stops right away, and the comments say "Stopped by @you" instead of "failed". Cancelling the workflow run also stops the agent.

This needs the stop-aware concurrency group from the current template, so the stop doesn't queue behind the run it stops.

Run checkpoints

When a run starts, the status comment links to the live run and stores an encrypted checkpoint. It's sealed with a key derived from your Netlify token, bound to the thread and runner, and never holds the prompt or site ID in plain text.

Set job-timeout-minutes to the job's timeout-minutes so the agent's own limit fits inside the job.

Scope guard

Risky files get flagged for review

After a run, the action checks which files it changed and adds a ⚠️ Review these changes table to the result comment, and to the PR for runs started from an issue. It never blocks a run.

It flags workflows, netlify.toml, root *.toml files, lockfiles, AGENTS.md and CLAUDE.md, .env files, new files at the repository root and new top-level folders. Files the request names are listed as requested instead.

Change the list with protected-paths (globs; a pattern without / matches only at the root; default, none and !pattern work), and escalate with protected-paths-action: comment,label,draft. By default, scope-instructions also tells agents to report unrelated build or deploy failures instead of working around them.

Recovering runs

Runs finish even if the job dies

Sometimes the agent keeps working on Netlify after its GitHub job is gone. The checkpoint records that the run never finished, and there are two ways it gets finished.

On the next @netlify comment

Before starting the new request, the action finishes the previous run. It waits for it if it's still working (up to 40% of the agent time limit), then opens the PR or reports the result and mentions whoever asked.

If the branch changed since the run started, it reports the result instead of landing it. If the thread was closed, the workflow was cancelled or the run ran out of time, it stops the run and lands nothing.

On a schedule (optional)

Copy netlify-agents-recover.yml into .github/workflows/. Every 30 minutes it checks threads updated in the last 48 hours and dispatches your main workflow with recover_thread for each unfinished run.

A scan with nothing to do takes about 20–30 seconds of Actions time. The main workflow needs the recover_thread input, the thread-scoped concurrency group and actions: read, as in the current template.

Dry runs and preflight

Try it without landing anything

dry-run and preflight-only are different controls.

  • dry-run: 'true' still starts an agent run, but skips commit and PR creation.
  • preflight-only: 'true' validates setup and exits before any agent run is created or resumed.
  • If both are true, preflight-only wins and no agent run starts.
- uses: netlify-labs/agent-runner-action@v1
  with:
    netlify-auth-token: ${{ secrets.NETLIFY_AUTH_TOKEN }}
    netlify-site-id: ${{ secrets.NETLIFY_SITE_ID }}
    preflight-only: 'true' # setup validation only

- uses: netlify-labs/agent-runner-action@v1
  with:
    netlify-auth-token: ${{ secrets.NETLIFY_AUTH_TOKEN }}
    netlify-site-id: ${{ secrets.NETLIFY_SITE_ID }}
    dry-run: 'true' # run agent preview, skip commits/PR

    id: agent
    with:
      netlify-auth-token: ${{ secrets.NETLIFY_AUTH_TOKEN }}
      netlify-site-id: ${{ secrets.NETLIFY_SITE_ID }}

  - name: Run tests on agent PR
    if: steps.agent.outputs.outcome == 'success'
    run: echo "PR created at ${{ steps.agent.outputs.agent-pr-url }}"

Security

Who can start a run, and what runs where

  • Only repository collaborators, members and owners can start a run, and allowed-users can narrow that further.
  • Bot accounts (github-actions[bot], netlify-coding[bot], netlify[bot]) are skipped, so the action can't trigger itself.
  • One run per issue or PR at a time, through the workflow's concurrency group.
  • Only status comments carry run state. Result comments are scrubbed so prose from users or agents can't plant state markers.

The trust model behind pull_request_target

The workflow uses pull_request_target so PRs from forks can start runs. That trigger has access to your secrets and a write-scoped token, which GitHub Security Lab warns can become a "pwn request". The action is safe under it because it checks the author's association before checkout and drops outside contributors, and because it never runs PR code on the runner: the agent runs on Netlify.

If you change the workflow, don't add steps that run PR code, such as npm install, tests, linters or builds against the checkout. That turns it into a way to steal your secrets. If you need to run PR code, use the two-workflow pull_request + workflow_run pattern from the GitHub Security Lab article.

Versioning

Follow @v1, or pin a release

Releases are tagged vX.Y.Z, and v1 always points at the latest v1.Y.Z release. Use @v1 to follow minor and patch releases automatically, or pin a release commit with a version comment (@<sha> # v1.2.0) and let Dependabot's github-actions updates propose upgrades.

Breaking changes (removed or renamed inputs and outputs, incompatible comment markers, or mention syntax that selects something different) only ship in a new major version. Release notes call out behavior changes and any workflow-file updates needed to use new features.

Troubleshooting

When something goes wrong

Missing NETLIFY_AUTH_TOKEN or NETLIFY_SITE_ID

Add both secrets under Settings > Secrets and variables > Actions. Create a token here, and find the Site ID in the Netlify dashboard under Site configuration > General.

Preflight checks failed

Read the preflight-summary and preflight-json outputs. Common causes: a token and site ID that don't match, an invalid default-agent, a non-positive timeout-minutes, or missing workflow permissions (contents: write, pull-requests: write, issues: write).

"The project can't be found"

NETLIFY_SITE_ID points to a site that doesn't exist or that the token can't access. Check the site ID in the Netlify dashboard and regenerate the token if needed.

The agent timed out

The default is 10 minutes. Raise it with timeout-minutes: '15' for bigger requests, or split the work into smaller follow-up comments on the PR.

A dry run still contacted Netlify

That's expected. dry-run only skips the commit and PR. Use preflight-only: 'true' to validate with no agent run.

"Requested agent is not available"

That agent is temporarily unavailable. Try another one: @netlify claude, @netlify codex or @netlify gemini.

The workflow runs on bot comments

Add the job-level if: guard from the setup workflow, which skips github-actions[bot], netlify-coding[bot] and netlify[bot].

A monorepo builds the wrong app

Set netlify-site-id to the Netlify site for that app. netlify-filter is only kept so existing workflows don't break.
